# Provider certification (wave 143, lane 143H)

For every provider this repository reaches: the API / SDK / MCP / webhook contract it speaks, how it is routed, whose credential it uses, how a tenant is kept apart, what a call costs and where that is booked, how a failure is retried and recorded, and which offline proof covers the response mapping. The three tables below are **derived** from the live registries (`deriveProviderAdapters`, `WEBHOOK_CONTRACT`) by `scripts/operations-docs-guard.ts`, which fails when this page drifts from them.

## 0. What "certified" means here — and what it does not

| Level | Meaning | Status in this document |
|---|---|---|
| **C — contract** | The provider is a declared kernel connection: a pinned API version, a base URL, a credential model, a cost booking, a health policy and a route; `validateAdapterSet` refuses a routed provider with no declaration, a declaration nobody routes, and a platform-paid adapter with no usage ledger. A base URL carrying a vendor-documentation source is *verified against the vendor*; otherwise it is *registry only*. | **Certified** for every adapter in §1 (the set validates with zero refusals). |
| **R — response mapping** | An offline test feeds the provider's documented response shape (fixtures in the repo) through our mapper and asserts the mapping. | **Per provider, §5.** Where no such proof exists the cell says so. |
| **L — live** | A real call with a real credential succeeded. | **Not performed — for any provider.** No provider credential exists in this environment and the owner ruling forbids acquiring one; no provider sandbox was used. Live certification is the activation checklist (§4 of `ACTIVATION-CHECKLIST.md`) and the Go-Live board's vendor probes. |

A provider is therefore *code-certified, live-unverified* until its key exists and its probe or console test delivery has passed. The two are never conflated: a simulated result is never reported as a live-provider success.

## 4. How the platform treats every provider (common behaviour)

**One egress.** A capability is requested, not a vendor (owner law 3): caller → `routeCapability` (`CONTACT_PROVIDER_ROUTES`, `lib/ai-isa/property-lookup-rail.ts:314`) → `callConnector` (`lib/agentic-os/connector-gateway.ts:218`) → provider. A provider reached outside those rails is listed with a published reason in the "Outside the rails" column of §2 — never silently.

**Timeout and retry** (`lib/agentic-os/connector-gateway.ts`): each attempt aborts after **15 s** unless the caller sets `timeoutMs` (`:352`); a **GET** retries once with a 400 ms back-off on a transient failure (429, any 5xx, or a thrown fetch/timeout; `:260-271`); **non-GET requests are never retried**, because a retried POST can double a spend or a message; a caller with a hard latency budget can switch the GET retry off (`retry: false`). A thrown fetch never escapes — it returns `ok:false` with a null status, which the ledger records as `network_or_timeout`.

**Failure recording and routing-around.** Every call writes an `api_response_logs` row typed `network_or_timeout` / `rate_limited` / `provider_error` / `request_rejected`. Provider health is *derived from that ledger* (no extra vendor call): within a 30-minute window, three consecutive provider faults mark the provider **failing** and `routeCapability` skips it for a 10-minute cool-down, then the next call probes it; a 20 % fault rate marks it degraded (`PROVIDER_HEALTH_POLICY`, `connector-gateway.ts:414-420`). The next provider in the route table's order is the fallback (§2 "Fallback"). A failing provider is *repaired* by `healProviderFailure` (`lib/agentic-os/connector-healer.ts:257`): probe → declared config alternate applied → retry → evidence; a code-level change only ever becomes a healing *proposal* for a human.

**Credential model and tenant isolation.** Two models only. *Platform env key* — one key in the environment, metered per call and attributed to the tenant that caused it. *Tenant connection* — the tenant's own credential, an AES-256-GCM row (`lib/security/secret-crypto.ts`), read only after a session-derived tenant gate (CLAUDE.md §4; never a tenant id from a request body). The ownership of each provider is stated by `lib/providers/tenancy-matrix.ts` (`platform_metered`, `platform_subaccount`, `user_oauth`, `tenant_optional_key`, `byo_top_tier`). Property providers never receive a lead's identity (`npm run test:leads-never-reach-property-providers`); Twilio gives each tenant a subaccount; a tenant's Stripe account is a connection, never an env var (`lib/billing/stripe-account-scope.ts`).

**Cost booking.** Platform-paid calls book to `vendor_usage_tracking` through `meterVendorSpend` (`lib/vendor-governance/meter-vendor.ts:46`); AI inference books to `ai_tool_usage` through `logAIUsage` (`lib/ai/cost-tracking.ts:154`) — that table is the invoice. A price is a typed state (`fixed`, `variable`, `unknown`, `free`, `tenant_account`); an unknown price is *declared*, never $0-by-default. `validateAdapterSet` makes "no unmetered paid capability" a failing check, not a convention.

## 8. Blind spots (published beside the numbers, CLAUDE.md §2)

- agentic capabilities: rows are the CALLABLE ones (an executor, or a DELEGATION_WORKERS survivor bound through requestDelegation); 48 manifest entries are catalog-only (refused by name on tools/call) and counted, not rows
- webhook triggers: a provider console registration cannot be read from code — an exported handler on a callback path is taken as reachable; http triggers count only in-repo `/api/…` literals (an external caller reads as no trigger — unresolved, not dead, CLAUDE.md §1)
- server actions: a path is the export + its same-file callees + the WHOLE-FILE facts of each local module it references (one hop; a lib module's facts are module-level — over-reports writes, under-reports anything two hops away); a computed import specifier is not an edge
- manager-signal consumers from runtime import of lib/kernel/manager-signals.ts SIGNAL_HANDLERS; a publisher is a file that calls publishManagerSignal AND carries the type as an exact string literal (a type built at run time is invisible)
- planes and A7.1 surfaces are a LEXICAL lens over the entry path, action name and written tables (a row may sit on several planes; an unmatched row is '(unclassified)')
- readback = a reader of a written table in ANOTHER file via `.from(t).select` (an RPC, a view or a trigger-maintained reader is invisible); evidence = a ledger door (OUTCOME_RE / DOOR_TOKENS) or a write to a ledger-shaped table on the path
- decision owner = the first authority / arbiter / approval / spend / compliance token (PLANE_RES) or outbound gate on the path, a session read for a human-initiated action, or a verified provider signature for a webhook; a gate two hops away is invisible

## Event and action naming (wave 97)

- **Existing events keep their names.** `KernelEvent` values (`lib/kernel/events.ts`) are not renamed: renaming one would orphan every stored row and every `notification_rules.trigger_event`.
- **New events and every ledger action use `domain.entity.action`**: lowercase snake segments, for example `comms.email.send`, `comms.direct_mail.send`, `welcome.decision.wait`, `agent.decision.do_nothing`. The ledger enforces this in code (`lib/kernel/action-ledger.ts`) and in m687 (`agent_action_ledger_action_format_check`).
- **Causation:** a row's `causation_id` is the event being processed when it was written. Its `correlation_id` is the chain root, which every descendant inherits. The root row has neither, so query with `id = X OR correlation_id = X`.
- **Reason codes** form one vocabulary (`ACTION_REASON_CODES`, mirrored by the m687 CHECK, and `test:action-ledger` derives both sides). Add new codes; never respell an existing one.
